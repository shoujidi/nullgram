# Nullgram 提醒

版本 13.0.8（1282）。安装包名为 `top.nkbe.niagram`。

## 使用方法

1. 在希望监听的账号中，进入「设置 → Null设置 → 提醒」。
2. 顶部「启用提醒」是总开关，新安装默认关闭。升级保留旧关键词总开关状态。
3. 「关键词提醒」子开关只控制文字包含匹配，升级保留原来的关键词及行为。
4. 点击「添加特别关注人」，从联系人或用户名搜索中选择人员。
   也可以打开私聊或群成员的个人资料，在菜单中选择「添加特别关注人」。
5. 在人员选项中分别开启「私信发言提醒」「群组发言提醒」「频道发言提醒」「上线提醒」或「私聊已读提醒」并保存。
   新人员各项默认关闭；点击已有人员可更改范围或删除。
6. 开启总开关。仅监听开启时绑定的单个账号；切换页面账号不会自动更换监听账号。
   要更换监听账号，先关闭总开关，切换账号，再重新开启。

人员名单按账号用户 ID 分开保存在本地，每个账号最多 100 人，名称只是显示信息。
关闭总开关保留全部配置，不清除之前已显示的通知。

## 发言提醒

- 仅处理绑定账号实际收到的新消息，不扫描历史，不监听自己发出的消息。
- 私聊、群组、频道分别控制；静音及归档聊天也适用。
- 频道评论按关联讨论群的群消息处理。
- 频道帖子必须明确携带个人发送者 ID；不凭署名、昵称、转发来源识别人。
  匿名管理员和以频道身份发送的消息不能对应关注人。
- 支持文字和非文字消息；非文字通知使用通用摘要，点击可查看原消息。
- 同一消息同时命中关键词和关注人，只产生一次独立提醒。
  使用账号身份、dialogId 和 messageId 去重；最近 512 个已发布事件有界持久化，淘汰后不保证无限期去重。
- 点击通知沿用现有聊天、消息和话题导航。登出或账号槽位被其他账号占用后，旧通知安全降级。

## 上线提醒的边界

- 仅使用 Telegram 原连接提供的可见状态，不添加账号连接、不轮询、不启动额外后台服务。
- 首次观察及重新连接后的状态只建立基线，不立即提醒。
- 观察到明确离线状态转在线时提醒。在线有效期结束后收到新的在线状态也会检查该转换。
- 最近在线、上周在线、未知等模糊状态不作为明确离线证据。
- 同一人在 60 秒内不重复提醒，成功提醒时间按账号及人员在本地保存。
- 上线通知显示人员名称，点击打开其私聊，不声称存在一条对应消息。
- 状态事件可能被合并或遗漏；隐私、网络、应用被系统停止以及后台连接限制都会影响提醒。
  这是「观察到对方在线」，不是对每次真实上线的完整记录。

Telegram 说明：
[在线状态可见性](https://telegram.org/faq#q-who-can-see-me-online)、
[状态更新](https://core.telegram.org/constructor/updateUserStatus)。

## 私聊已读提醒

- 使用绑定账号的 Telegram 出站已读回执。仅跟踪开关开启后从本机普通私聊发出的消息。
- 一次回执覆盖多条已确认发送的消息时，合并提醒并定位到其中最新一条。
- 已读事件保存在特别关注记录。记录时间是本机观察到回执的时间，断线后收到的回执也以观察时刻为准。
- 每人最多保存最近 512 条已取得服务器消息 ID 的待回执消息。重启后用 Telegram 原有会话同步和出站回执补确认，重复同步只记录一次。
- 关闭总开关、个人已读提醒或退出账号会清除对应的待回执名单。重新开启后从新发送的消息开始跟踪。
- 沿用特别关注的系统通知和应用内横幅，不轮询已读名单或查询精确阅读时间。

## 关闭和兼容性

总开关关闭时直接跳过匹配及状态处理，注销本模块自己的观察者，取消待发布任务，
以版本号拦截已经出队的旧任务，不写入新的提醒去重记录。
重连仅取消上线提醒任务，不取消已排队的发言提醒。

普通 Telegram 通知规则、聊天静音状态、通知权限、重复发送、快速复读和统一停止按钮均不改变。
沿用原独立提醒渠道 `nullgram_keywords_v1`，只更新显示名称，不重置用户设置的声音或重要性。
通知遵守 Android 权限、渠道设置、锁屏/应用密码锁及系统勿扰限制。

## 验证说明

自动化测试通过实际执行模块、SharedPreferences、NotificationCenter、Android 通知及设置对话框验证行为。
Telegram 网络、账号缓存和状态输入由测试夹具提供；这不等同于两台真实账号互发或真实上线事件验证。
最终 PASS / FAIL / NOT RUN、APK 路径及校验信息见交付报告。
